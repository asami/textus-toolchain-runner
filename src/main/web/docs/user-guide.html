Textus Component Developer Guide

Textus Toolchain Runner

Textus Toolchain Runner owns the Textus toolchain Docker image and exposes artifact conversion tools as CNCF component operations and as a ToolchainRunner SPI provider.

Document Routes

CNCF serves this guide as a component-packaged manual, separate from generated CML/component help. 

/man/{component}
/man/{component}/user-guide.html
/man/{component}/user-guide.md

The generated component specification is served at /help/{component}. If a packaged PDF is added as docs/user-guide.pdf, CNCF serves it at /man/{component}/user-guide.pdf. 

curl -fsS http://localhost:8080/man/textus-toolchain-runner/user-guide.md
curl -fsS -o user-guide.pdf http://localhost:8080/man/textus-toolchain-runner/user-guide.pdf

Source of Truth

This guide is the human-authored component developer manual for the running component. The component specification is managed beside the implementation in src/main/cozy/textus-toolchain-runner.cml. The CML file is the operation contract for generated APIs, CAR packaging, runtime integration, and component users.

Default Image

Docker image
ghcr.io/asami/textus-toolchain:latest
Wrapper command
textus-toolchain
Main conversion command
svg-pages-to-pdf

The image can be overridden by operation input or by runtime configuration using textus.toolchain-runner.docker.image.

Component Operations

convertSvgToPdf

Converts one SVG file into one PDF file through the toolchain image.

textus-toolchain-runner convert-svg-to-pdf --svg input.svg --out output.pdf

convertSvgPagesToPdf

Converts multiple SVG pages into one multi-page PDF.

textus-toolchain-runner convert-svg-pages-to-pdf \
  --svgFiles page-001.svg,page-002.svg \
  --out print.pdf

renderWebPage

Renders one HTTP(S) page through Playwright/Chromium and returns requested/final URL, status, title, rendered HTML, timestamp, engine, and browser. CNCF components should call the ToolchainRunner SPI; Textus Scraper is the standard rendered-HTML normalization boundary.

When to Use the Component

Use the component or ToolchainRunner SPI when the caller runs inside CNCF and needs structured operation results, CallTree/observability, configured Docker command selection, and controlled workspace handling.

Sanpomap uses this path when it generates SVG pages and delegates PDF conversion to ToolchainRunner.

Direct Docker Image Usage

Direct Docker use is for standalone CI jobs, local diagnosis, or tools that only need the packaged command-line environment and do not run inside CNCF.

Pull and Check

docker pull ghcr.io/asami/textus-toolchain:latest
docker run --rm ghcr.io/asami/textus-toolchain:latest textus-toolchain check all

Convert SVG Pages to PDF

docker run --rm -v "$PWD:/work" -w /work \
  ghcr.io/asami/textus-toolchain:latest \
  svg-pages-to-pdf --out print.pdf page-001.svg page-002.svg

Run Installed Tools Directly

The wrapper passes through commands when no Textus-specific command matches. 

docker run --rm ghcr.io/asami/textus-toolchain:latest antora --version
docker run --rm ghcr.io/asami/textus-toolchain:latest ffmpeg -version
docker run --rm ghcr.io/asami/textus-toolchain:latest python3 -c 'import PIL; print(PIL.__version__)'

Render a Web Page

Direct browser use is intended for deterministic CI and diagnosis. Put the request in request.json; output is written only to the requested response file. 

{
  "url": "https://example.org/application",
  "waitUntil": "networkidle",
  "waitForSelector": "#application",
  "timeoutSeconds": 30
}
docker run --rm -v "$PWD:/work" -w /work \
  ghcr.io/asami/textus-toolchain:latest \
  render-web-page request.json response.json

Diagnostics use stderr. Rendered HTML is not written to stdout.
